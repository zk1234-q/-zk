# 01 PRD

## 产品定位

Expense Bill Analyzer 是一个个人消费账单分析工具。

用户上传 iCost 导出的 Excel 或 CSV 账单后，系统自动解析消费数据，并生成按月份、一级分类、二级分类统计的分析表格。

第一阶段优先做本地单用户版本，不做登录、不做多用户、不做云端同步、不做复杂权限。

## 核心用户

- 使用 iCost 记录个人消费的用户
- 想按月份查看消费结构的用户
- 想知道钱主要花在哪些一级分类和二级分类上的用户
- 不需要复杂记账系统，只需要本地分析账单的用户

## 核心目标

第一版需要支持：

1. 上传 iCost 导出的 Excel 或 CSV 文件
2. 识别消费日期、金额、一级分类、二级分类等字段
3. 按月份汇总收入、支出、结余和结余率
4. 展示一级分类支出占比表
5. 展示二级分类支出占比表
6. 展示一级分类 + 二级分类综合表
7. 点击金额字段查看对应消费明细
8. 展示图表辅助分析消费结构
9. 展示异常数据列表，明确哪些记录未参与统计
10. 支持按月份保存历史账单到本地浏览器
11. 提供每月账单上传管理入口，方便后续做月份对比
12. 确保所有金额合计和原始账单能对得上

## 核心使用流程

1. 用户进入首页
2. 上传 iCost 导出的 Excel 或 CSV 文件
3. 系统解析文件并展示数据预览
4. 用户确认数据字段识别结果
5. 系统展示异常数据列表，提醒哪些记录未参与统计
6. 用户确认后保存该月份账单到本地
7. 系统生成月度汇总、分类统计表和图表
8. 用户切换月份查看不同月份数据
9. 用户点击金额字段查看对应明细

## 上传账单流程

- 支持 Excel 和 CSV 文件
- 上传后先做基础字段识别
- 需要识别消费日期、金额、类型、一级分类、二级分类、商户、备注、支付方式
- 如果字段缺失，需要在预览阶段明确提示
- 如果存在无法解析的行，需要单独标记，不直接混入统计

## 每月账单管理流程

系统需要提供按月份管理账单的入口。

用户上传并确认账单后，系统需要把该月份的标准化账单保存到浏览器本地。

账单管理列表需要展示：

- 月份
- 是否已上传
- 上传文件名
- 上传时间
- 支出笔数
- 月总支出
- 异常记录数

如果同一个月份重复上传账单，第一版先提示用户确认是否覆盖该月份已有数据。

本地保存只保存在当前浏览器中，不上传服务器，不跨设备同步。

## 表格展示流程

系统需要生成以下表格：

1. 月度汇总表
2. 一级分类支出占比表
3. 二级分类支出占比表
4. 一级分类 + 二级分类综合表

表格需要支持：

- 月份切换
- 按金额排序
- 金额字段可点击
- 百分比字段清晰展示

## 图表展示流程

第一版需要增加图表辅助分析，但图表不替代表格，表格仍然是金额核对的主要依据。

第一版图表包括：

1. 月度总支出趋势图
2. 一级分类支出占比图
3. 二级分类支出排行图

图表需要跟随当前选择月份变化。

月度总支出趋势图展示已保存月份的总支出变化，为后续月份对比功能做准备。

## 异常数据列表流程

异常数据不能直接混入统计，需要在预览阶段单独展示。

异常数据列表需要展示：

- 原始行号
- 异常原因
- 原始日期
- 原始类型
- 原始金额
- 原始一级分类
- 原始二级分类
- 原始备注

用户确认后，异常数据仍然保留在本地记录中，但不参与支出统计。

## 点击金额查看明细流程

点击不同金额时，弹框展示不同范围的账单明细：

- 点击总支出：展示该月份所有支出明细
- 点击一级金额：展示该月份、该一级分类下的所有支出明细
- 点击二级金额：展示该月份、该一级分类、该二级分类下的所有支出明细

弹框底部需要展示：

- 明细笔数
- 明细合计金额

明细合计金额必须和被点击的金额一致。

## 异常数据处理规则

- 默认只统计类型为“支出”的记录
- 不把“借入”“转账”“退款”“收入”算入消费支出
- iCost 导出的支出负数金额按绝对值计入支出
- 退款、借入、转账等特殊记录需要单独列出处理规则
- 不确定类型的数据需要在预览或异常列表中提示
- 月份按消费日期归属
- 非完整月份需要标注“非完整月，仅参考”
- 异常数据需要单独展示数量和原因

## 默认业务口径

- 默认月收入为 9000 元
- 月份按消费日期计算
- 支出统计只包含消费支出
- 第一版先做本地分析，不做账号体系

## 未来可扩展功能

- 支持自定义月收入
- 支持多账本
- 支持预算设置
- 支持后端数据库
- 支持多用户登录
- 支持更多账单来源

## 第一版验收标准

1. 可以上传 iCost 导出的 Excel
2. 可以识别消费日期、金额、一级分类、二级分类
3. 可以按月份汇总
4. 可以展示一级分类表
5. 可以展示二级分类表
6. 可以展示一级 + 二级综合表
7. 点击一级金额可以查看对应明细
8. 点击二级金额可以查看对应明细
9. 可以展示月度总支出趋势图
10. 可以展示一级分类支出占比图
11. 可以展示二级分类支出排行图
12. 可以展示异常数据列表，并说明异常原因
13. 可以把确认后的月份账单保存到浏览器本地
14. 可以在账单管理页查看已保存月份
15. 同月份重复上传时需要提示覆盖
16. 所有金额合计能对得上原始账单
17. 所有占比公式正确
18. 页面能在本地正常运行

# 第二版 PRD：本地增强版（待确认）

## 第二版产品定位

第二版先做“本地增强版”，继续以当前浏览器本地保存为主，不引入后端、账号登录和云端数据库。

第二版解决三个明确问题：

1. 月度分析里的默认月收入不能写死为 9000，需要用户可以设置。
2. 新增账单大类预算，用户可以设置年支出总预算、月攒钱预算、月总支出预算和每月各一级分类预算。
3. 新增独立的手工购物预算表，用户自己维护预算、购买数量、实际购买金额和购买内容。
4. 重复上传同一月份账单时，保存前给出更清楚的覆盖确认信息。
5. 设置里提供本地数据导出和导入，让用户可以手动把当前电脑的数据迁移到另一台电脑。
6. 提供月度预算总览和月度结算视图，帮助用户判断当月预算和攒钱目标是否达成。

云端保存、账号登录、跨设备查看属于第三版规划。原因是云端必须能识别数据属于哪个用户，需要后端、数据库和用户身份体系，不能在第二版里顺手加。

## 第二版核心目标

1. 用户可以修改默认月收入，月度分析从设置读取收入值。
2. 用户可以设置年支出总预算、月攒钱预算金额、月总支出预算。
3. 用户可以按月份手工维护各一级分类预算，分类名称不写死。
4. 如果当月账单已导入，系统按一级分类名称自动反写该分类已支出金额和剩余预算金额。
5. 月度分析的一级 / 二级综合分类明细表需要根据已设置的大类预算判断是否超支。
6. 一级分类金额超出该月该大类预算时，一级分类总支出金额标红。
7. 点击一级分类总支出金额时，需要展示预算状态小窗，说明预算、已支出、剩余或超出金额。
8. 用户可以复制已有月份的大类预算到新月份，再手工微调。
9. 用户可以从已导入账单的一级分类中选择大类名称，也可以手工填写。
10. 用户可以在月度预算总览中查看月收入、月总支出预算、当前已支出、剩余预算、月攒钱目标和预计攒钱结果。
11. 用户可以在月度结算视图中查看超支大类、剩余最多大类、总预算是否超支、月攒钱目标是否达成。
12. 用户可以维护一个独立的购物预算明细表。
13. 用户可以新增、删除、修改购物预算明细行。
14. 购物预算明细支持记录品类、计划数量、已购买数量、预算金额、单件实际购买金额和购买内容。
15. 系统按品类计算购物预算剩余金额。
16. 系统按行判断购物预算是否超支。
17. 实际购买小计超出预算时，实际购买金额和实际购买小计标红。
18. 购物预算表底部展示合计行，统计总预算金额、总实际购买金额、总剩余预算金额。
19. 重复上传同一月份账单时，系统在保存前展示已有账单和本次账单的对比信息。
20. 用户可以导出当前本地数据文件。
21. 用户可以在另一台电脑导入数据文件，恢复同一份本地数据。
22. 第二版所有新增数据仍保存在本地浏览器中，刷新页面后仍能看到。

## 第二版使用边界

第二版暂不做以下内容：

- 不做账号体系
- 不做云端同步
- 不做跨设备自动同步
- 不做自动云端备份
- 不自动把账单明细拆到购物预算表
- 不自动匹配账单里的服装、鞋子等消费记录
- 不做商品链接、价格抓取、自动推荐
- 不做复杂审批流
- 不做库存管理或衣柜管理

## 默认月收入设置

第一版默认月收入为 9000 元。第二版需要允许用户修改默认月收入。

### 设置字段

| 字段 | 说明 |
| --- | --- |
| 默认月收入 | 用户自己填写，月度分析默认读取该值 |
| 货币单位 | 第二版固定为人民币，不做多币种 |
| 保存时间 | 记录设置最后更新时间 |

### 使用规则

- 月度分析页的收入、结余、结余率、分类占收入比例，都需要读取默认月收入。
- 如果用户没有设置，继续使用 9000 元作为默认值。
- 默认月收入保存在本地浏览器中，刷新页面后不丢失。
- 第二版先不做不同月份不同收入，所有月份统一读取同一个默认月收入。

## 账单大类预算

账单大类预算用于控制每个月各一级分类的支出上限。

该功能和第一版账单分析结果联动，但只按“月份 + 一级分类名称”匹配，不自动分析具体商品或二级分类。

### 总预算设置

用户需要可以设置以下总预算字段：

| 字段 | 说明 |
| --- | --- |
| 年支出总预算 | 用户计划全年最多支出的总金额 |
| 月攒钱预算金额 | 用户计划每月攒下的钱 |
| 月总支出预算 | 用户计划每月最多支出的总金额 |

第二版先只保存这些总预算字段，并在预算页展示。是否用它们约束每月大类预算总和，后续实现时可以先做提醒，不强制禁止保存。

### 月度大类预算字段

用户可以按月份维护大类预算行。

| 字段 | 说明 |
| --- | --- |
| 月份 | 格式 YYYY-MM，例如 2026-06 |
| 大类名称 | 用户手工填写，需要和账单一级分类名称一致，例如汽车、餐饮、服饰 |
| 大类预算金额 | 用户为该月份该大类设置的预算 |
| 已支出金额 | 如果当月账单已导入，系统按一级分类名称自动计算 |
| 剩余预算金额 | 大类预算金额 - 已支出金额 |
| 是否超支 | 已支出金额 > 大类预算金额 |
| 备注 | 用户手工说明 |

### 大类名称规则

大类名称不写死，由用户手工填写。

如果当月账单已导入，预算设置页需要提供该月账单已有的一级分类名称选择入口，用户可以直接选择，减少名称不一致导致的匹配失败。

用户仍然可以手工填写大类名称，用于提前设置还没有出现在账单里的预算分类。

匹配规则建议先采用精确匹配：

```text
同一个月份内，预算大类名称 = 账单一级分类名称
```

实现时可以去掉前后空格再比较，避免用户误输入空格导致匹配失败。

第二版不做模糊匹配。例如“汽车”和“车”不自动认为是同一类。

同一个月份内，同一个大类名称建议只允许一条预算记录，避免重复预算导致计算混乱。

### 复制月份预算

每个月的大类预算通常有重复性。第二版需要支持把某个月的大类预算复制到另一个月份。

复制规则：

- 用户选择来源月份和目标月份。
- 系统复制来源月份的大类名称、预算金额和备注。
- 已支出金额、剩余预算金额、是否超支需要按目标月份重新计算，不能直接复制来源月份的计算结果。
- 如果目标月份已经存在预算，需要二次确认后才能覆盖。
- 第二版先不做部分合并复制，避免同一月份同一大类出现重复预算。

### 账单导入后的反写规则

如果用户已经导入某个月账单，再新增或修改该月份的大类预算行：

- 如果大类名称能匹配到账单一级分类，系统自动反写已支出金额。
- 剩余预算金额自动计算。
- 如果已支出金额大于大类预算金额，显示超支状态。
- 如果大类名称匹配不到任何账单一级分类，已支出金额显示 0，并提示“未匹配到账单分类”。

如果用户先设置预算，后导入该月份账单：

- 账单保存成功后，需要重新计算该月份所有大类预算的已支出金额和剩余预算金额。

### 月度预算总览

预算管理页需要提供月度预算总览，让用户快速判断本月预算状态。

月度预算总览字段：

| 字段 | 说明 |
| --- | --- |
| 月份 | 当前查看月份 |
| 月收入 | 读取默认月收入 |
| 月总支出预算 | 用户设置的月总支出预算 |
| 当前已支出 | 当月账单已导入时，取当月总支出 |
| 当前剩余预算 | 月总支出预算 - 当前已支出 |
| 月攒钱预算金额 | 用户计划本月攒下的钱 |
| 预计可攒金额 | 月收入 - 当前已支出 |
| 攒钱目标状态 | 预计可攒金额是否达到月攒钱预算金额 |

如果当月账单未导入，当前已支出显示 0，并提示“当月账单未导入，预算执行仅供填写参考”。

### 月度分析联动

一级 / 二级综合分类明细表中，一级分类金额需要读取该月对应大类预算。

如果存在该月该一级分类预算：

```text
是否超支 = 一级分类总支出金额 > 该月该大类预算金额
```

如果超支，一级分类总支出金额字段标红显示。

如果没有设置该分类预算，则不做超支判断，也不标红。

### 预算使用率颜色

账单大类预算需要用颜色表达预算使用率：

| 使用率 | 状态 | 显示规则 |
| --- | --- | --- |
| 小于 80% | 正常 | 普通显示 |
| 80% 到 100% | 接近预算 | 使用提醒色 |
| 大于 100% | 已超支 | 金额标红 |

预算使用率公式：

```text
预算使用率 = 已支出金额 / 大类预算金额
```

如果大类预算金额为 0，且已支出金额大于 0，直接视为超支。

### 预算提示小窗

用户点击一级分类总支出金额时，除现有明细弹框能力外，需要能看到预算提示信息。

建议设计为点击金额后优先打开消费明细弹框，并在弹框顶部或侧边展示预算信息：

- 大类名称
- 本月预算金额
- 本月已支出金额
- 剩余预算金额
- 超出预算金额
- 预算使用率

显示文案规则：

```text
未超支：还剩 X 元预算
已超支：已超出 X 元预算
未设置预算：该大类本月未设置预算
```

这样比单独弹一个小窗更稳，因为用户点击金额本来就会查看明细，预算状态和明细放在一起更容易理解。

### 超支备注

如果某个月某个大类预算超支，用户需要可以填写超支备注。

超支备注用于解释为什么超支，例如：

- 本月汽车保养
- 临时购买鞋子
- 聚餐较多

超支备注只用于用户自己回看，不参与计算。

### 月度结算视图

第二版需要提供月度结算视图，帮助用户在月末复盘。

月度结算视图展示：

- 本月总预算是否超支
- 本月月攒钱目标是否达成
- 超支的大类列表
- 剩余预算最多的大类列表
- 每个大类的预算金额、已支出金额、剩余金额、使用率、超支备注

月度结算视图只做展示和复盘，不自动修改预算。

## 手工购物预算管理

第二版新增一个独立的手工预算管理功能。

该功能不和第一版账单分析表联动，不从账单明细自动读取消费数据。用户自己维护预算明细、购买数量、实际购买金额和购买内容，系统只负责保存、展示、计算是否超支。

第一批使用场景以“服装预算管理”为主，但功能本身不限制只能管理服装，也可以维护鞋子、配饰或其他个人预算明细。

## 购物预算明细表字段

预算明细表建议包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 品类 | 例如主力外套、副手外套、裤子、鞋子、卫衣 / 内搭、T 恤 / 短袖、机动资金 |

## 购物预算计算规则

### 实际购买小计

“实际购买金额”按单件单品金额填写。

```text
实际购买小计 = 已购买数量 * 实际购买金额
```

### 行是否超支

每行按该行自己的预算金额和实际购买小计判断是否超支：

```text
行是否超支 = 实际购买小计 > 预算金额
```

如果某行超支，该行的“实际购买金额”和“实际购买小计”需要标红。

### 品类剩余预算金额

剩余预算金额按品类计算。

同一个品类可能有多行明细，例如“裤子”可以有冬天款、夏天款、多条裤子的不同记录。

```text
品类剩余预算金额 = 该品类所有行预算金额合计 - 该品类所有行实际购买小计合计
```

表格中每一行的“剩余预算金额”显示该行所属品类的剩余预算金额。

如果品类剩余预算金额小于 0，表示该品类整体超支。

### 合计行

表格底部需要有合计行，展示：

- 总预算金额
- 总实际购买金额
- 总剩余预算金额

合计公式：

```text
总预算金额 = 所有行预算金额合计
总实际购买金额 = 所有行实际购买小计合计
总剩余预算金额 = 总预算金额 - 总实际购买金额
```

如果总剩余预算金额小于 0，表示整体预算超支。

## 重复上传月份账单优化

第一版已经要求同月份重复上传时提示是否覆盖。第二版需要把覆盖确认做得更清楚。

### 保存前检查

用户上传账单并解析完成后，保存前需要检查本地账单管理中是否已经存在相同月份。

如果不存在，正常保存。

如果已存在，需要弹窗展示对比信息，让用户决定覆盖旧账单或取消保存。

### 覆盖确认信息

覆盖确认弹窗需要展示：

| 信息 | 已保存账单 | 本次上传账单 |
| --- | --- | --- |
| 月份 | 显示已有月份 | 显示本次识别月份 |
| 文件名 | 已保存文件名 | 本次上传文件名 |
| 上传时间 | 已保存上传时间 | 当前时间 |
| 原始行数 | 已保存原始行数 | 本次识别原始行数 |
| 有效支出行数 | 已保存有效支出行数 | 本次有效支出行数 |
| 异常行数 | 已保存异常行数 | 本次异常行数 |
| 月总支出 | 已保存月总支出 | 本次月总支出 |

### 覆盖规则

第二版只支持：

- 覆盖旧账单
- 取消保存

第二版不做合并账单。合并容易导致重复计算，风险高。

## 本地数据导出 / 导入

第二版需要在设置页或设置区提供本地数据导出和导入能力。

这个功能用于解决用户换电脑后数据无法带走的问题，但仍然不做云端账号和自动同步。

### 导出规则

用户可以点击“导出本地数据”，系统生成一个本地数据备份文件。

导出文件需要包含：

- 默认月收入设置
- 预算管理明细
- 每月账单数据
- 每月账单的文件名、上传时间、行数、有效支出行数、异常行数、月总支出

导出文件建议使用 JSON 格式，方便后续版本兼容和排查问题。

### 导入规则

用户可以在另一台电脑的设置页点击“导入本地数据”，选择之前导出的备份文件。

导入后，系统需要把备份文件里的数据写入当前浏览器本地存储，让当前电脑恢复到导出时的状态。

导入前必须二次确认，因为导入可能覆盖当前浏览器已经存在的本地数据。

第二版导入策略建议先采用“整包覆盖”：

```text
导入后当前本地数据 = 导入文件中的数据
```

第二版暂不做“合并导入”。合并会引入重复账单、重复预算行和冲突处理，复杂度不适合当前阶段。

### 导入校验

导入前需要做基础校验：

- 文件必须是系统导出的 JSON 备份文件
- 文件中必须包含版本号
- 文件中必须包含用户设置、预算明细、月度账单数据结构
- 文件格式不正确时不能导入，需要提示用户重新选择文件

## 本地保存规则

第二版仍然使用本地浏览器保存数据。

需要保存的数据包括：

- 默认月收入设置
- 年支出总预算
- 月攒钱预算金额
- 月总支出预算
- 月度大类预算
- 大类预算超支备注
- 预算管理明细
- 每月账单数据
- 每月账单的文件名、上传时间、行数、有效支出行数、异常行数、月总支出

用户每次进入页面时，系统优先读取上一次保存的数据。已填写的预算明细、默认月收入和已保存账单不能因为刷新页面而消失。

需要明确提示用户：本地保存只保存在当前浏览器中。如果用户清理浏览器数据、更换浏览器或更换设备，数据不会自动同步。

如果需要换电脑使用，用户需要先在旧电脑导出本地数据文件，再在新电脑导入该文件。

## 第三版云端规划

用户希望换电脑后也能查看历史账单和预算。这个目标需要云端保存。

云端保存必须有账号体系，否则系统无法识别账单属于谁。

第三版建议再设计：

1. 用户登录 / 注册
2. 云端保存账单
3. 云端保存预算管理明细
4. 云端保存默认月收入设置
5. 换电脑登录后读取同一份数据

第三版云端数据需要至少包含 `userId`，账单、预算、用户设置都需要绑定到对应用户。

第二版建议新增或调整以下页面：

1. 设置页或设置区：维护默认月收入、导出本地数据、导入本地数据
